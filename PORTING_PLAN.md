# Porting plan: Adaptive Chess → native Swift + SwiftUI

Branch `swift-native`. The TypeScript app in `src/` is the specification. This document records the
rules of the port, how every TS file becomes Swift, which phase does it, and what each phase must prove
before it is committed.

## RULES

- Goal: a native Swift + SwiftUI app whose features, rules, AI behavior, tuning numbers, UI text and visual design match the TypeScript app. The TS in src/ is the spec. Port logic 1:1: same algorithms, constants, tables, thresholds, strings and save-data shape. Don't redesign or "improve" gameplay.
- Decisions: iOS 17+ (the package also supports macOS 14 so tests run on the Mac). SwiftUI + Observation (@Observable). Swift 6 language mode if it compiles cleanly, otherwise Swift 5 with strict concurrency warnings. Apple frameworks only: no third-party packages, CocoaPods or npm in the final app. Work on branch swift-native, commit once per phase, never commit or push to main.
- Toolchain: prefix every xcodebuild/xcrun/swift command with DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer. Simulator destination 'platform=iOS Simulator,name=iPhone 17 Pro'. Build with CODE_SIGNING_ALLOWED=NO (no Apple Developer account).
- Layout: Packages/ChessCore holds ChessCore (Engine/, AI/) and ChessServices (clock, puzzles, progression, storage, store, controller). The AdaptiveChess app target holds UI/, DesignSystem/, Platform/ (sound, haptics) and Resources/.
- Porting gotchas:
  - Use fixed-width integers for the packed 32-bit moves, and respect JS >>> vs >>.
  - Use Swift's wrapping operators (&+ &* &<<) wherever JS wraps, e.g. mulberry32 and hashing. Zobrist keys are UInt64.
  - Seeded RNGs must be bit-identical: zobrist.ts mulberry32 and the date-seeded daily puzzle.
  - Math.random becomes an injectable RandomNumberGenerator so tests can fix it.
  - Keep Double where TS does float math (eval noise, Elo) and Int where values are integral.
  - Use stable sorts wherever tie order matters (move ordering, root move choice).
  - Codable models must read and write the exact JSON shape that TS JSON.stringify produces: same keys, and missing fields omitted rather than null.
- Parity: when unsure about behavior, run the TS (node/tsx/vitest) to generate expected values and assert them in Swift tests.
- Quality: no stubs, TODOs or placeholders in finished phases. Fix every error and warning you introduce. If the TS has a bug, port it faithfully and log it under "Faithfully-ported bugs". Every phase ends with its check passing, the checklist ticked and a commit "Phase N: …".

## Faithfully-ported bugs

- **En-passant square from FEN is always hashed (position.ts `loadFen` vs `makeMove`).** `makeMove` records `ep` only when an enemy pawn can actually capture (FIDE position identity), but `loadFen` takes the FEN's ep square verbatim and `computeHash` XORs it in. So `…/PPPP1PPP/RNBQKBNR b KQkq e3 0 1` loaded from FEN hashes to `qsljuo.x3ajeo`, while the identical position reached by playing 1.e4 hashes to `9741ik.tbz9di`. Only affects repetition counting in games started from such a FEN. Ported as-is; both values are asserted in `ZobristTests`.
- **`loadFen` does not reset the king squares.** `kingSq` keeps its previous value (`[4, 60]` initially) for a side whose king is missing from the FEN. Position is only ever loaded with two kings by the app, so it is harmless; ported as-is.
- **`normalizeSAN`'s second replace is a no-op (san.ts).** `.replace(/^([RNBQK])([a-h1-8]?)x/, '$1$2x')` rewrites the match to itself, so the function only strips a trailing run of `+#!?` and trims. Swift does exactly that and documents the dead step in a comment.
- **The `dead-position` result kind is unreachable (game.ts `checkAutomaticEnd`).** `isDeadPosition` is a pure material test (neither side has mating potential) and every material set that satisfies it also satisfies `isInsufficientMaterial`, which is tested first. Such games therefore always end as `insufficient` with "Draw — insufficient material"; the `dead-position` kind and its message "Draw — dead position" exist but never fire. Ported as-is; `EnginePortTests` pins the overlap.
- **A PGN tag line with trailing text is not a header (pgn.ts `fromPGN`).** The header regex demands end-of-line right after `]`, so `[White "A"] ; comment` is left in the move text and the import throws `Illegal or unparseable PGN move: [White`. Ported as-is (asserted in `EnginePortTests`).
- **`planForGame` ignores `aiColor` (adaptation.ts).** `const closedSign = aiColor === WHITE ? 1 : 1;` evaluates to 1 for both colours, so the tactical counter-plan sets `closedPref = 0.8` regardless of side — combined with the White-only closed-centre bonus above, the AI only seeks a locked centre when it plays White and avoids one as Black. Ported as-is (`aiColor` is accepted and unused); `AdaptationTests.aiColorIgnored` pins that both colours yield identical plans.
- **An unfinished game is a draw for the record but a loss for king safety (playerModel.ts).** `updateModelAfterGame` treats `game.result?.winner === undefined` like `null` (draw: `draws++`, `streak = 0`, score 0.5), while `extractWeaknesses` tests `winner !== null && winner !== playerColor`, which is true for `undefined`, so a never-castled player gets a `king-safety` bump for a game that has no result. Ported as-is (`PlayerModelTests.unfinishedGame`, replay step 3 of the fixture).
- **A corrupt primary copy hides the good secondary copy (storage.ts `loadKey`).** `loadKey` falls back from Capacitor Preferences to localStorage only when the native value is `null`; when the native string exists but does not parse, `JSON.parse` throws and the `catch` returns `null` without consulting localStorage, so the crash-safe second copy is never used for a torn primary. `Storage.load` does the same: the file is read first and the UserDefaults copy is consulted only when the file is absent (`StorageTests.dualWrite` pins it). In practice the atomic file write cannot produce a torn file, so the case needs a corrupted disk.
- **A mating puzzle move plays the win fanfare twice (controller.ts).** `validatePuzzleMove` calls `puzzleSolved()` (`sound.gameWin()` + `haptic.success()`) and `playMove` then reaches `onGameEnd()`, which plays `gameWin` + `success` again because the puzzle mode is not `pvp` and the player won. Ported as-is; `GameControllerTests.endFeedback` pins both calls.
- **A pending post-game analysis lands on the next game (controller.ts `runPostGameAnalysis`).** `newGame` clears `analysis` but not `analysisPending`, and the `.then` handler has no `moveSeq` guard, so when the analysis of the previous AI game finishes after a new game started, `analysis` shows the old game's grades in the new one (the archive attachment is guarded by the UCI line and the model update is intended, so those are fine). Ported as-is: the analysis task deliberately survives `newGame` (cancelling it would lose the model update and the recorded mistakes) and is cancelled only by `dispose()`.
- **`thinking` stays true after resigning while the AI is searching (controller.ts).** `resign()` never resets `thinking`, so the flag is left set until the next `newGame`; harmless because the game is finished. Ported as-is (Swift additionally cancels the request).
- **The closed-centre bonus is a White bonus (eval.ts).** `score += params.closedPref * locked * 8` is added to the white-perspective score without a side sign, and the search negates the eval for Black (`side * evaluate(...)`). An AI with `closedPref > 0` therefore likes locked central pawns when it plays White and avoids them when it plays Black. Ported as-is; `EvalTests.symmetry` skips the `closedPref` parameter sets for that reason and the eval parity fixtures pin the behaviour for both colours.

- **Phase 6 API notes:** `GameController(state:ai:feedback:timeSource:random:)` is `@Observable @MainActor`; every TS field is a `public private(set)` observable property (`hintsLeft` stays settable because the TS test assigns it), `subscribe`/`emit` become Observation plus a `revision` counter that `emit()` bumps, `gameId` is kept for the UI. `newGame(mode:playerColor:difficulty:timeControl:challenge:startFen:)` / `newGame(_ opts: NewGameOptions)` throw the `Position` FEN error (the TS throws from `new Game(fen)`); `ChallengeContext {puzzle, drill, constraint, isDaily, mistake}` is the TS challenge object, `PuzzleState` the `'solving' | 'wrong' | 'solved'` union, `PostGame {notes, offersReady}`. `resume(_:)` is `@discardableResult`. `dispose()` cancels everything incl. the analysis and the clock; `cancelAIWork()` (new game, undo, resign) cancels the move, pacing timer, hint, draw-decision and mate-in-N check tasks — the TS cannot cancel its worker and drops stale replies through `moveSeq` only, which Swift keeps as a second line of defence (a `CancellationError` never triggers the failsafe move; any other error does). One deliberate deviation: the TS mate-in-N check (`requestHint` after the first puzzle move) has no `moveSeq` guard, so a slow reply could mark the *next* puzzle wrong; Swift cancels that task on `newGame`. `ClockTimeSource` grew `now: Date` (wall clock for `savedAt`, archive `date`, mistake `date`, the PGN `Date` header and `completeDaily`) and `schedule(afterMs:)` (`setTimeout`, used for the 450 ms reply pacing); `ManualTimeSource.nowMs` doubles as Unix milliseconds so tests freeze both clocks at one instant (`Harness.epoch` = 2026-06-01T09:00:00Z, the vitest fake-timer date). `AIService` is `Sendable` with `move` / `hint` / `analyze` (the actor satisfies it directly); `FeedbackService` is `@MainActor` with `play(_ sound: SoundEvent)` / `trigger(_ haptic: HapticEvent)`. The controller records `inflightRequests` (internal) so tests can `drain()` — yield until every started request has finished or parked — before asserting on requests, because the TS issued them synchronously; `settle()` = drain, advance 500 ms, drain. Sound synthesis: each `tone(freq, dur, type, gain, when)` is a `Voice` in a lock-protected `VoiceBank` mixed by one mono `AVAudioSourceNode`: `v(t) = gain · (0.0005 / gain)^(t / dur)` for `t < dur`, then 0.0005 until `dur + 0.02`, sine / triangle / square oscillators with phase accumulation, output clamped to ±1. `audio()` mirrors the TS: nil while `settings.sounds` is off, lazy engine creation, restart when the engine is not running (the `resume()` of a suspended AudioContext). The app target compiles with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, so the render-thread types (`Voice`, `VoiceBank`) are marked `nonisolated`.
